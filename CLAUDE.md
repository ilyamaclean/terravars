# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`terravars` is an R package providing fast terrain, hydrological and canopy-derived spatial predictor variables for microclimate downscaling and general terrain/GIS analysis (solar index, sky-view factor, topographic wetness index, wind shelter/altitude, coastal exposure, two-stream canopy radiation, basin delineation/flow routing). It is built around the `terra` package (`SpatRaster` in/out throughout) and implements all performance-critical computation in C++ via `Rcpp`.

Not yet on CRAN; installed from GitHub (`ilyamaclean/terravars`).

## Commands

Run from an R console with the working directory set to the package root (or via `Rscript -e`):

- Load for interactive development: `devtools::load_all()`
- Full check (build, run tests, run examples, `R CMD check`): `devtools::check()`
- Run the test suite only: `devtools::test()`
- Run a single test file: `devtools::test(filter = "twi")` (matches `tests/testthat/test-twi.R`; filter matches against the file name minus `test-`/`.R`)
- Run a single test file directly: `testthat::test_file("tests/testthat/test-solar.R")`
- Regenerate `man/*.Rd`, `NAMESPACE` `export()` entries from roxygen comments: `devtools::document()`
- Recompile C++ sources and refresh `R/RcppExports.R` / `src/RcppExports.cpp` after editing any `src/*.cpp`: `Rcpp::compileAttributes()`, then `devtools::load_all()` (or `devtools::document()`, which calls both)
- Build the vignette / package docs site locally: `pkgdown::build_site()` (if `pkgdown` is configured) or `devtools::build_vignettes()`

There is no linter or formatter configured for this package.

## Architecture

### R/C++ split

Each `R/*.R` file has a matching `src/*.cpp` file; the R side validates arguments, prepares `terra` objects into plain matrices/arrays, and calls into C++ worker functions (suffixed `_cpp`) via `Rcpp::sourceCpp`/`.Call`. `R/RcppExports.R` and `src/RcppExports.cpp` are generated by `Rcpp::compileAttributes()` — never hand-edit them; edit the `// [[Rcpp::export]]`-tagged C++ functions instead and regenerate.

| R file | Exported functions | src file |
|---|---|---|
| `R/solar.R` | `solarindex()`, `horizon()`, `skyview()`, `twostream()`, `canopy3d()` | `src/solar.cpp` (consolidated: clear-sky, solar position, horizon/sky-view, two-stream, 3D ray-marched vegetation attenuation) |
| `R/wind.R` | `wind_shelter()`, `wind_altitude()`, `coastalexposure()` | `src/wind.cpp` |
| `R/wetness.R` | `basindelin()`, `basinmerge()`, `fillsinks()`, `flowacc()`, `flowpath()`, `twi()` | `src/wetness.cpp` |
| `R/download.R` | `dem_download()`, `landcover_download()` | (pure R; no C++ — see below) |
| `R/data.R` | roxygen documentation only for bundled datasets (no functions) | — |
| `R/utils.R` | internal (unexported) R-side helpers shared across the above | — |
| `src/utils.h` | shared C++ constants/inline helpers (degree/radian conversion, grid indexing, clamping) included by every `src/*.cpp` | — |

`R/download.R` is the only file that performs network I/O (direct HTTPS requests to public, unauthenticated AWS S3 buckets — `elevation-tiles-prod` for DEM tiles, `esa-worldcover` for land cover — no API keys). Both download functions tile/mosaic manually rather than depending on `elevatr`/`sf`.

### Shared conventions worth knowing before editing any function

- **Projected CRS required.** Every function taking a `dtm`/terrain-like `SpatRaster` calls `.check_projected()` (`R/utils.R`) and errors if the raster is geographic (lon/lat) rather than projected (metre units) — `terra` has no `is.projected()`, so this is done via `!terra::is.lonlat()`.
- **Azimuth/direction convention.** All compass directions (`azi`, `wdir`, etc.) are degrees, N = 0, clockwise, and are searched *directly toward* that azimuth (not `+ 180`) — `horizon()`, `wind_shelter()`, and `coastalexposure()` all rely on this being consistent.
- **NA / land-sea convention.** `NA` cells conventionally represent sea or no-data. Several functions (`fillsinks()`'s `waterbody`, `coastalexposure()`'s `landsea`) key off this.
- **`fillna` argument pattern.** `solarindex()`, `twi()`, `twostream()` share a `fillna = TRUE` option (via `.fillna_dtm()`/`.nn_fill()` in `R/utils.R`) that nearest-neighbour-fills `NA` cells and the DTM's own outer ring before a `terra::terrain()` slope/aspect call (which otherwise returns `NA` in a halo around any `NA` cell and along the raster edge), then masks the result back to the true `NA` pattern afterwards.
- **Padded-matrix worker convention.** `basindelin()`, `basinmerge()`, `fillsinks()`, `flowacc()` all pad their input matrix by 1 cell (`.pad1()` in `R/utils.R`, sentinel `9999` for elevation) before calling their C++ worker, so every real cell has 8 well-defined neighbours and the raster's own edge doubles as an implicit outlet — then strip the border back off the result.
- **Bundled example datasets are wrapped.** `dtm100m`, `pai`, `hgt`, `vegx`, `landcover`, `dtmc` (`data/*.rda`, documented in `R/data.R`) are stored as `terra::wrap()`ed `PackedSpatRaster` objects (a live `SpatRaster` holds a C++ pointer that can't survive `save()`/`load()`); always unwrap with `terra::rast(dtm100m)` etc. before use. Functions that accept these as arguments (e.g. `coastalexposure()`'s `coarse`) auto-unwrap `PackedSpatRaster` input so callers can pass bundled data straight through. All bundled rasters share `dtm100m`'s grid (100 m resolution, OSGB36 / British National Grid) except `dtmc`, a coarser two-level regional extension used to let `coastalexposure()` searches reach beyond `dtm100m`'s own extent.
- **Optional per-cell parameters.** Leaf/canopy parameters (`x`, `lref`, `ltra`, `gref`, etc.) accept a scalar, `NA`/`NULL` (default), or a `SpatRaster`; resolved to a matrix via `.to_mat()` (`R/utils.R`). `lref + ltra < 1` is enforced by `.check_leaf_optics()` wherever both apply.
- **Two calculation "speed modes"** recur across `horizon()`, `solarindex(shade=)`, and `skyview()`: `nstep = 0` (default) exhaustively checks every intervening cell out to the raster edge; `nstep > 0` switches to a sparser, faster quadratically-spaced search. Ray-marched 3D vegetation paths (`hgt` argument to `solarindex()`/`skyview()`, and `canopy3d()`) warn via `.warn_ray_march_cost()` when the estimated runtime (raster size × total sky directions) looks large.
- **`pai_horiz`** (`solarindex()`, `twostream()`) declares whether a supplied plant-area-index raster is per unit horizontal or sloped ground area; the two differ by `cos(slope)` and are converted internally so results are physically consistent regardless of convention.

### Tests

`tests/testthat/` (edition 3) has one file per function group (`test-twi.R`, `test-skyview.R`, `test-solar.R`, `test-wind.R`, `test-basins.R`), generally built on small synthetic rasters constructed inline (e.g. a flat plain with hand-placed pits) rather than the bundled Lizard-peninsula datasets, so expected values can be reasoned about exactly.

### Vignette

`vignettes/tutorial.Rmd` is the single tutorial vignette, walking through every exported function grouped by theme (solar radiation → wind/coastal exposure → hydrology → data download → building a combined predictor stack), using the bundled Lizard peninsula (Cornwall, UK) datasets throughout. Code chunks are `eval = FALSE` with pre-rendered images in `vignettes/images/`.
